## Stage-to-Stage Data Contract

The entire `ServiceRequestGraphState` (including `collected_data` and `backend_refs`) is persisted to PostgreSQL by `save_state_node` at the end of every turn and reloaded by `load_session_node` at the start of the next. This means all data collected in earlier stages is automatically available in later stages. The contract below makes those dependencies explicit.

### Stage 1 → Stage 2 (CREATE_SR produces → FM_REVIEW consumes)

`collected_data` fields carried into FM_REVIEW (read-only to the FM reviewer):

| Field | Source |
|---|---|
| `lease_id`, `lease_code`, `mall`, `brand` | Lease lookup in CREATE_SR |
| `unit_code`, `unit_type` | Tenant-supplied in CREATE_SR |
| `description` | Tenant-supplied in CREATE_SR |
| `title` | Auto-generated by `merge_state_node` |

`backend_refs` fields carried forward:

| Field | Source |
|---|---|
| `sr_id` | Returned by POST `/service-requests` on SR creation |
| `tenant_profile_id`, `property_id` | Set during CREATE_SR; required for all subsequent PATCH/POST calls |

FM_REVIEW **adds** to `collected_data`:
- `unit_readiness_date` — FM Manager sets this via conversation
- `expected_handover_date` — auto-computed as `unit_readiness_date + 7 days` (see Task 2.3; never asked from user)

FM_REVIEW **adds** to `backend_refs`:
- `uploaded_documents` — list of FM document IDs (see Task 2.1)
- `fm_status` — set to `APPROVED` after PATCH succeeds

### Stage 2 → Stage 3 (FM_REVIEW produces → RDD_REVIEW consumes)

`collected_data` fields available to the RDD reviewer (read-only; all Stage 1 fields plus):

| Field | Source |
|---|---|
| `unit_readiness_date` | Set by FM Manager in Stage 2 |
| `expected_handover_date` | Auto-computed in Stage 2 |

RDD_REVIEW **adds** to `collected_data`:
- `handover_meeting_date`, `technical_handover_date`, `commercial_handover_date`, `contractual_handover_date` — DD Engineer enters these

RDD_REVIEW **adds** to `backend_refs`:
- `rdd_document_id` — handover report document ID (see Task 2.1)
- `rdd_status` — `REPORT_SUBMITTED` then `APPROVED` (see Task 2.5)

## Task 2.1 — Implement `document_upload_node`

**File:** `backend/app/agents/graph/nodes/document_upload_node.py`

Replace the empty stub with a pure state bridge — no API calls, no LLM:

```python
"""Bridge uploaded document IDs from state["documents"] into backend_refs.

Reads state["documents"] (list of {document_id, document_type_id, ...} written by
POST /api/upload → draft.documents → load_session_node → state["documents"]).

Partitions by document type:
  FM docs (SR_HANDOVER_CHECKLIST, SR_HANDOVER_SITE_SURVEY, SR_COP_CHECKLIST_OTHER)
    → backend_refs["uploaded_documents"]  (consumed by fm_payload_builder)
  RDD report (DR_SR_HANDOVER_REPORT)
    → backend_refs["rdd_document_id"]     (consumed by rdd_payload_builder)
"""
from app.agents.schemas.handover_schema import FM_ALLOWED_DOCUMENTS, RDD_REQUIRED_DOCUMENTS
from app.observability.decorators import trace_node

@trace_node("document_upload", "CHAIN")
async def document_upload_node(state) -> dict:
    documents: list[dict] = state.get("documents") or []
    backend_refs: dict = dict(state.get("backend_refs") or {})

    fm_doc_ids: list[str] = []
    rdd_doc_id: str | None = None

    for doc in documents:
        doc_type = doc.get("document_type_id", "")
        doc_id = doc.get("document_id")
        if not doc_id:
            continue
        if doc_type in FM_ALLOWED_DOCUMENTS:
            if doc_id not in fm_doc_ids:
                fm_doc_ids.append(doc_id)
        elif doc_type in RDD_REQUIRED_DOCUMENTS:
            rdd_doc_id = doc_id   # last wins (single report expected)

    # Merge — preserve any IDs already set from prior turns
    existing_fm = backend_refs.get("uploaded_documents") or []
    merged_fm = list({d for d in existing_fm + fm_doc_ids})
    backend_refs["uploaded_documents"] = merged_fm

    if rdd_doc_id:
        backend_refs["rdd_document_id"] = rdd_doc_id

    return {"backend_refs": backend_refs}
```

**File:** `backend/app/agents/schemas/handover_schema.py`

3. Remove it from `EXTRACTABLE_FIELDS` so the LLM never tries to extract it.

**File:** `backend/app/agents/graph/nodes/merge_state_node.py`

After merging extracted fields into `collected_data`, add FM-stage auto-calculation:

```python
from datetime import datetime, timedelta

def _add_days(date_str: str, days: int) -> str:
    """Add calendar days to a YYYY-MM-DD date string."""
    for fmt in ("%Y-%m-%d", "%d/%m/%Y", "%d-%m-%Y"):
        try:
            dt = datetime.strptime(date_str, fmt)
            return (dt + timedelta(days=days)).strftime("%Y-%m-%d")
        except ValueError:
            continue
    return date_str  # fallback: return unchanged if unparseable

# Inside merge_state_node, after merging:
stage = state.get("workflow_stage") or ""
if stage == "FM_REVIEW":
    readiness = collected.get("unit_readiness_date", "")
    if readiness and not collected.get("expected_handover_date"):
        collected["expected_handover_date"] = _add_days(readiness, 7)
```

```python
def build_rdd_approve_payload(
    backend_refs: dict[str, Any],
    comment: str = "",
) -> dict[str, Any]:
    """PATCH payload for RDD final approval (status=APPROVED).
    
    Mirrors fm_approve shape — minimal body, no lease_code/lease_id at top level.

    sr_id: str = backend_refs.get("sr_id", "")

        "payload": {
            "comment": comment,
            "user_action": None,
            "current_sr_status": "APPROVED",
            "sr_id": sr_id,
        },
        "status": "APPROVED",
        "service_request_id": sr_id,
        "service_category": "FIT_OUT_AND_HANDOVER",
        "sub_category": "HANDOVER",
        "tenant_profile_id": backend_refs.get("tenant_profile_id"),
        "property_id": backend_refs.get("property_id"),
    }
```
